0.15.0

MDK 0.15.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.14.0 → 0.15.0 client upgrade guide for required record, error, event, header, storage and interoperability changes.

Read full notes

MDK 0.15.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.14.0 → 0.15.0 client upgrade guide for required record, error, event, header, storage and interoperability changes.

Highlights

  • Accounts with several devices. Creating a group or inviting adds every device of each account (up to 20 KeyPackages published in the last 30 days, or the single best valid one when none is that recent), and members are listed once per account with a device_count. A device joins only through the Welcome that names its own KeyPackage. New groups whose founding devices all support it require the account-devices component (marmot.group.account-devices.v1); an admin can turn it on in an existing group with enable_account_devices.
  • Automatic rejoin. An account worker rejoins a group copy that became Unrecoverable through an authenticated handshake with an admin device over the account inbox, with bounded retries.
  • Recovery owns account history. Catch-up after time offline is bounded and paced, history arrives in order, newer live messages wait until the fetched backlog is admitted, and account_recovery_status reports groups still catching up. A rejoined group raises one BeforeRejoin history notice.
  • Chat-list queries. Typed filters (unread, pinned, archived, direct, group, muted, chat text, message text and more) combine with AND/OR/NOT, and hosts can select every chat a filter matches for bulk actions.
  • Timeline search filters by sender, date range and attachment type, and matches non-ASCII text case-insensitively.
  • Sonar-compatible sticker packs, NIP-51 custom emoji sets with pinned local installs, and custom reaction artwork lookup.
  • Leaving as an admin. A blocked leave (the last active admin) is shown and can be cancelled with cancel_leave. sign_out_and_wipe steps an admin down and leaves the chats another account also administers before wiping.
  • Push notifications reach every device of a member, newly added members learn existing tokens, and devices repair missed tokens inside each group.
  • Sends: queued offline sends publish after reconnect, a send never overtakes one queued before it, a Welcome waits until its Commit is published, failed convergence retries back off and park, and refused queued intents are retired with QueuedIntentRefused. Oversized events report EventTooLarge.
  • KeyPackages are valid for 30 days and refreshed weekly. Sign-out deletes only this device's KeyPackage slot instead of every device's.
  • External signers are no longer asked to sign the identity proof again on every reopen.
  • Pasted note1, hex and author-only nevent references now resolve through the deployment's discovery indexers and the author's write relays.
  • WN Agent: wn-agent doctor, a connector-only install-wn-agent.sh for your own control-socket client, historical attachment download with leases, founding co-admins, and default relays with published relay-list adoption.
  • Lower idle cost: maintenance ticks with nothing to do no longer open write transactions, wnd no longer grows about 3 MB per request, and cached user search ranks in SQL and finds people past the 10,000th cached identity.
  • Security: the pinned Nostr SDK rejects tampered events even when their id is cached, directory events are verified before they are forwarded or stored, account records are written owner-only, local audit files expire after 30 days, and elliptic-curve/HPKE (RUSTSEC-2026-0387), openssl and the OpenClaw plugin's npm dependencies are updated.

Experimental device groups (pairing, linked devices, sign-in review, history transfer and backups) continue behind the dev-device-groups build feature and new_with_experimental_device_groups. Ordinary builds and constructors keep them off and refuse accounts that already use them.

Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort together.

  • Interoperability: every 0.15 device advertises the account-devices component. A new group requires it when the creator and every device added at creation advertise it, and 0.14 or older clients cannot then be invited into it. Existing groups are unchanged until an admin enables it.
  • TimelineMessageQueryFfi adds sender, since, until and cursorGroupId with no binding defaults. MarmotDeploymentFfi drops keyPackagePreferredClients and keyPackageLastClients.
  • MarmotKitError gains 22 cases, including EventTooLarge, MediaReferenceStaleEpoch, MediaReferenceEpochUnsettled, LeaveNotBlocked, InvalidChatListQuery, AccountUnlinked, the sticker and emoji-set errors, and GroupRecoveryUnsettled/GroupRecoverySourceMismatch. Some failures that used to arrive as Runtime, Publish or InvalidMediaReference now use them, and busy, closed or full storage arrives as StorageBusy, StorageClosed or StorageFull.
  • MarmotEventFfi gains eight cases, and WelcomeDeliveryPending gains sizeClass. HistoryNoticeCauseFfi gains UnprovenHistory and BeforeRejoin; SelfMembershipFfi and ConversationParticipationFfi gain DeviceRemoved; GroupEventKindFfi gains QueuedIntentRefused.
  • Media references saved by 0.14 lack sourceEpochIdentity; sending one is refused with MediaReferenceStaleEpoch, so re-upload instead.
  • Admin invitees must step down before declining an invitation, and OnboardingIssueFfi::MultiDeviceUnsupported is no longer produced.

C hosts must recompile. marmot_deployment_set_key_package_client_preference is removed. MarmotMediaAttachmentReference gains source_epoch_identity mid-struct; message, timeline, chat-list preview and notification records gain a sticker pointer mid-struct; MarmotTimelineMessageRecord gains recipient_confirmed mid-struct; MarmotClientOptions and MarmotTimelineMessageQuery gain trailing fields. Statuses 108–129 and enum values are appended; none is renumbered.

Rust hosts: cgka-session is now marmot-session, TimelineMessageQuery and chat-list query types gain fields and variants, AppError gains variants, and the diagnostics exporters move to marmot-observability. See the upgrade guide.

Account databases migrate from schema 116 through 201 on first open. Downgrade is unsupported: 0.14.0 refuses the migrated database. Keep a device-local copy of the account directory before upgrading. See the storage-format contract.

Building from source now needs the Odin compiler (scripts/install-odin.sh, or set ODIN), because Markdown parsing moved to Odin. Published artifacts are unaffected.

WN Agent and its plugins must be upgraded together: a 0.15.0 client sending a new request, such as group_create_capabilities, to a 0.14.0 connector sees the socket close without an error. The OpenClaw plugin requires OpenClaw 2026.10.10 or newer and Node 24.22.1+ (24.x) or 26.12.1+.

Known issues

  • Still open from 0.14.0: #2237 (late messages more than five epochs behind), #2277, #2283, #2389 and #2286 (group-change prompts), #2253 (group data extension order), #2158 (an upload in flight across an epoch change is lost) and #1445 (WN Agent's control socket grants its whole API to any authenticated client).
  • Adding every device of an account is best effort: a device whose KeyPackage a relay does not return in time is left out until the account is invited again, and an account for which one relay returns a full page (500) of KeyPackages or of KeyPackage deletion requests cannot be invited.
  • Right after a reconnect, a new send can still go out ahead of older unsent ones.
  • A failed legacy group create in an earlier release can have left orphaned MLS state; 0.15 stops creating it but does not purge it.
  • Migration 0175 refuses to open an account whose saved outbound fanout or group evolution does not decode, rather than risk reusing a send reference.
  • The automatic-rejoin handshake's inner event kind is still under discussion (marmot#451).

Release artifacts

  • v0.15.0: MDK source snapshot; workspace crates remain unpublished to crates.io.
  • wn-agent-v0.15.0: WN Agent, terminal harness binaries, gateway plugins and checksum-paired installers, now including install-wn-agent.sh.
  • marmotkit-v0.15.0: iOS/macOS XCFrameworks, shared Swift source, platform privacy resources, Android Kotlin and all four JNI ABIs with android-elf.json, manifests and checksums.
  • marmotc-v0.15.0: C library/header bundle and checksum.

Verify sibling SHA-256 files and source/version manifests; Apple binary ZIPs also have SwiftPM checksums. Follow the distribution guide. Dated 0.15.0-nightly.* builds are for testing only; pin this release instead.

0.14.0

MDK 0.14.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.13.0 → 0.14.0 client upgrade guide for required constructor, record, error, header, storage and backup changes.

MDK 0.14.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.13.0 → 0.14.0 client upgrade guide for required constructor, record, error, header, storage and backup changes.

Highlights

  • Encrypted media files. Attachment bodies, download checkpoints, avatars and group images move out of the account database into encrypted per-file storage under the account's media/ directory. Bodies already in the database move in the background, and a one-time compaction returns the freed space when the account is small enough.
  • Manage storage. Hosts can show per-account and per-chat attachment usage, list the largest retained attachments, and remove a chat's attachments or everything older than a date. "Keep media" removes attachments past a chosen window (one year, six months or thirty days) on this device.
  • Attachment handoff leases give the OS share sheet or another app a plaintext copy of one attachment, released explicitly.
  • Account-wide attachment history pages list media across every chat with filters, bounded pages and change tokens.
  • Public event previews resolve and cache nostr: references in messages, and report when the author deleted the event.
  • Faster database opens. App databases now present their derived key to SQLCipher as a raw key instead of a passphrase, skipping a 256,000-iteration KDF on every open. Each existing database is rekeyed once on first open.
  • Group changes can pause with a prompt: GroupCatchingUp while the device is still catching up, and GroupCommitUndelivered when the previous commit has not reached its relays for two minutes. The host acknowledges and retries; messages and leaving are never held.
  • Invitations explain failures: a recipient whose only KeyPackages are obsolete, a lookup that ran out of time, or a member with no inbox route.
  • Follow and unfollow edit the current follow list in place, keeping petnames, relay hints and other tags, and refuse instead of truncating a list of 2,048 or more.
  • WN Agent can edit an agent's own message (edit_message), and OpenClaw exposes it. Edits of messages that cannot be edited are refused before anything is published.
  • MarmotKit runs MDK on its own two-to-four-thread runtime, so async calls awaited from the main thread no longer run MDK work there.
  • Deployment services that used to be compiled in for White Noise (recovery relays, discovery indexers, media and image servers, Open Ranking, KeyPackage client preference, moderation namespace, keychain service) are now one host-supplied deployment record with a White Noise preset.
  • Catch-up and delivery: ordered, complete offline catch-up; live group subscriptions batched 50 per REQ so accounts in many groups stay under relay REQ limits; epoch-gap recovery pages backwards through clamped relays; terminal relay rejections are no longer retried; stalled recovery routes stay retryable; self-update commits retry every missed relay.
  • Onboarding relay diagnostics say which check produced each finding, why it ran, what it found and which actions apply to it.
  • An unreachable relay no longer fails an account's activation or group sync, taking the inbox and every healthy group offline; its subscription is sent when the relay reconnects, and a group sync re-sends only the relay sets it changes. Sends and group changes no longer fail when the pre-send subscription refresh cannot reach a group's relays; convergence retries and signed-out accounts still require it. Opt-in relay telemetry exports activation and group-sync outcome counters.
  • Fixes: the retention sweep no longer deletes messages still counted unread; a quarantined group no longer stalls every conversation's receives; iOS suspension no longer risks 0xdead10cc termination; a Welcome built from a just-replaced KeyPackage can still be joined.
  • QUIC agent-stream brokers are verified against bundled Mozilla roots, fixing an Android abort on the first handshake.
  • Security updates: quinn-proto, rustls, rustls-webpki, webpki-roots, negentropy and ctutils.

Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort together.

  • Every MarmotKit constructor takes a MarmotDeploymentFfi, and MarmotOptions.deployment is required. White Noise apps pass marmotDeploymentWhiteNoise(). Other hosts that used the platform keychain without a SecretStore must keep keychainService = "com.marmot.whitenoise", or their existing account secrets are no longer found.
  • MarmotKitError gains InvalidEditTarget, InvalidPublicEventReferences, DirectoryLookupIncomplete, FollowListTooLarge, GroupCatchingUp, GroupCommitUndelivered and StorageFull; MissingKeyPackage gains a reason. Some failures that used to arrive as Runtime or InvalidKeyPackageEvent now use the new variants.
  • AttachmentTransferStateFfi gains StorageBlocked and CleanedBySetting; RetentionSweepStatusFfi loses DeferredScanExhausted.
  • OnboardingFindingFfi gains context, purpose, outcome, declaredCapability, actions and observedRevision with no binding defaults, and OnboardingIssueFfi gains InspectionCompleted.

C hosts must recompile and update every marmot_client_new* call: each takes a required const struct MarmotDeployment *. MarmotRetentionSweepStatus drops DEFERRED_SCAN_EXHAUSTED, so FAILED moves from 5 to 4. MarmotOnboardingFinding changes layout, MarmotOnboardingIssue appends InspectionCompleted (21), and statuses 101–107 are new. No other existing struct layout changed.

Rust hosts: MarmotAppConfig::default() is now the neutral deployment; use MarmotAppConfig::white_noise() to keep White Noise's services. MarmotApp's directory methods moved to app.directory() and return DirectoryError. AppError gains six variants, ingestion borrows its input, and NostrAdapterMetrics and RelayTelemetryRollup gain counter fields.

Account databases migrate from schema 107 through 116 on first open, the directory cache from 1 to 2, and every app database is rekeyed to a raw SQLCipher key. None of this rewrites message history, but the rekey rewrites every database page once. Downgrade is unsupported: 0.13.0 cannot open the rekeyed databases. Keep a device-local copy of the account directory before upgrading, and exclude the account directory, including media/ and handoff/, from iCloud and Android backups. See the storage-format contract.

WN Agent and its plugins must be upgraded together: a 0.14.0 plugin calling edit_message on a 0.13.0 connector sees the socket close without an error.

Known issues

  • #2237: a message that arrives more than five epochs too late stays undecryptable without a "history may be incomplete" notice.
  • Group-change prompts: undecryptable traffic can hold a group's changes behind GroupCatchingUp (#2277), no bounded catch-up runs before the refusal (#2283), and an acknowledgement cannot be withdrawn (#2389). Healthy relays can look owed for a short time after a commit (#2286); the two-minute grace keeps that from prompting.
  • #2253: group data updates move the app-data extension to the end of the group context, which implementations that preserve extension order reject.
  • #2158: an upload still in flight when the group epoch advances is lost.
  • The one-time rekey has not been measured on large databases or on devices beyond a Pixel 8 Pro fixture; see the upgrade guide.
  • WN Agent's control socket still grants its whole API to any authenticated client (#1445), and reports the new group-change refusals as a generic app_error.

Release artifacts

  • wn-agent-v0.14.0: WN Agent, terminal harness binaries, gateway plugins and checksum-paired installers. This track keeps its existing prerelease status.

  • marmotc-v0.14.0: C library/header bundle and checksum.

MDK 0.13.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.12.0 → 0.13.0 client upgrade guide for required record, error, event, header and storage changes.

MDK 0.13.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.12.0 → 0.13.0 client upgrade guide for required record, error, event, header and storage changes.

Highlights

  • Large attachments. uploadMediaFiles uploads from a file path with progress and cancellation instead of passing whole files as byte arrays, and large downloads stream into private files with resumable checkpoints.
  • Private moderation reports. submitModerationReport sends a NIP-56 report, gift-wrapped per NIP-59, to the deployment's moderation team. Relays cannot see who reported whom, and reports carry no message, group or relay identifiers.
  • Onboarding: createIdentityWithInitialProfile publishes the chosen name as a new account's first profile, so contacts never see the generated default. proposeOnboardingRelayRepair previews a lossless relay-list repair before approval, and manual relay edits keep untouched tags as they were.
  • Message details: messageReactions returns every reaction on one message. Markdown gains local-time timestamp nodes. Attachment history marks inline custom-emoji artwork so galleries can leave it out.
  • Polls can be created in direct conversations.
  • Chat list: presented rows carry an opaque draft version, so a host can tell a newer draft from the one it captured for sending.
  • Opt-in SOCKS5 routing (WN_SOCKS5_*) covers relays, media, directory reads, collectors and C NIP-46 sessions, and never falls back to a direct connection.
  • Opt-in native startup diagnostics report anonymous startup and migration phases for slow-open investigations.
  • Catch-up: missed group history arrives in batched requests of up to 256 events and, when the backlog is larger than one pass, oldest first. Commits no longer routinely move a member more than five epochs past messages it has not downloaded yet (#2086).
  • Relays that refuse a live subscription with CLOSED no longer leave it counted as live. Refusals are audited and counted in relay stats, and sync drains stop waiting for them.
  • Sends: a message queued while the group converged is no longer shown as failed after everyone else received it, and durable sends keep progressing through recovery and relay retries.
  • Invitations recover a member's KeyPackage from discovery relays when their advertised outboxes do not have one.
  • Marmot C adds per-account NIP-46 signer sessions (beta).
  • WN Agent adds the wn-goose harness for Goose and carries account relay-list reads and edits on the control surface.

Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort together. No existing exported method changed its signature, but:

  • MarmotKitError gains five moderation-report variants.
  • Native events gain LocalGroupCopyTerminated, LocalGroupCopyRestored and GroupMemberLeavesRemoved; MarkdownInlineFfi gains Timestamp.
  • AttachmentEntryFfi.role, PresentedChatRowFfi.draftVersion and OnboardingRepairProposalFfi.relayRepair are new fields without binding defaults. Update exhaustive handling and host-constructed records.

C hosts must recompile: MarmotAttachmentEntry, MarmotPresentedChatRow and MarmotOnboardingRepairProposal change layout, new event and Markdown inline tags are appended, statuses 96–100 are new, and relay-repair preview strings are JSON-encoded.

Rust hosts: AppError, GroupEvent, MarmotAppConfig, AttachmentEntry, RelaySyncSnapshot, NostrAdapterMetrics and NostrReconciliationSummary gain variants or fields. External-signer account database keys move into the host SecretStore on first open, so those accounts cannot be downgraded either.

relay.damus.io is no longer a retired relay; relay.nostr.band remains retired.

Account databases migrate from schema 101 through 107 on first open. The attachment migrations keep payloads in place, so opening does not copy message or attachment history. Back up before upgrading; downgrade is unsupported. See the storage-format contract.

Known issues

  • #2237: batched, oldest-first catch-up makes the #2086 loss much rarer, but it can still happen, for example when the only relay holding an old message is down. A message that arrives more than five epochs too late stays undecryptable without a "history may be incomplete" notice.
  • WN Agent's control socket still grants its whole API to any authenticated client; capability-scoped grants remain tracked in #1445.

  • marmotkit-v0.13.0: iOS/macOS XCFrameworks, shared Swift source, platform privacy resources, Android Kotlin and all four JNI ABIs with android-elf.json, manifests and checksums.
  • marmotc-v0.13.0: C library/header bundle and checksum.

Highlights

  • NIP-30 custom emoji. sendTaggedText, sendTaggedMedia and reactWithMedia send chats and reactions carrying ["emoji", shortcode, url] tags whose images are encrypted Marmot media. Conversation-window chat rows keep those tags, and reactions name the kind-7 whose image listMedia returns. Peers on 0.12.0 can send them, so render them.
  • Per-voter poll results. pollVotes pages who chose each option, using the same rules as the poll tally.
  • Application-owned group components. groupAppComponent and updateAppComponent read and admin-update opaque settings (ids 0xf000 and up) carried in MLS group state, so they survive message expiry and reach new members in their Welcome.
  • Hosts can declare a kind-10050 inbox relay list separately from default_relays on identity creation, login, relay-list publication and onboarding.
  • Attachments: agent-sent files no longer stay downloading forever, missing-key deferrals end after about eight minutes, an explicit tap (requestExplicitAttachment) promotes demand without resetting retry budgets, and successfully sent files are retained locally for the sender.
  • A muted chat still notifies on a direct mention of the account.
  • Recovery: a route change no longer resets recovery for every route, recovery parks behind a required relay that never answers, catch-up no longer holds the account worker for recovery, and group creation no longer rebuilds the routing table.
  • Publishing: retained per-account publishers cut a measured complete send-with-push call from about 1.9 s to 0.14 s mean against the operated relays.
  • WN Agent: admin agents can rename groups and edit descriptions (group_profile_update, Hermes marmot_group_profile); account_publish_profile merges into the published profile instead of replacing it; files work in both directions for Codex, OpenCode and Pi.

0.11.0

MDK 0.11.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.10.4 → 0.11.0 client upgrade guide for required record, schema, configuration and host UI changes.

Original notesGitHub release
Read full notes

MDK 0.11.0 releases the Rust workspace, WN Agent, MarmotKit (iOS, macOS and Android), and Marmot C from one source commit. See the 0.10.4 → 0.11.0 client upgrade guide for required record, schema, configuration and host UI changes.

A post-tag documentation supplement corrects both documents: polls are required, and v5 audit delivery replaces v4 for hosts that record audit logs. Host performance stages and pending-send edits are strongly recommended. Use the merged documentation commit for published links; the tagged copies predate this correction.

Highlights

  • Account recovery v2 completes lost or incremental history only when every required relay finishes an untruncated NIP-77 comparison that covers the gap. Recovery runs off the account worker and reuses live subscriptions instead of replaying history, and one comparison job replaces the inline executor.
  • When recovery cannot prove history complete, it stops retrying and raises a durable "history may be incomplete" notice. Hosts should show these notices and let the user dismiss them.
  • A full account delivery queue now spills to the account database instead of dropping deliveries. A relay notification lag no longer closes the account route, and end-of-stored-events notifications lost in a lag are repaired.
  • The transport cursor advances on live delivery, so a restart no longer re-downloads what the account already received live. History REQs for post-join maintenance and retained routes now start from a floor instead of fetching full history.
  • Encrypted NIP-88 polls. Every client must render, vote on and create them, because peers on 0.11.0 can send them.
  • Audit v5 replaces v4. With audit enabled, only v5 files are written, and the v4 Goggles whole-file route rejects them. Hosts that record audit logs must deploy a v5 OTLP receiver and configure it with setAuditOtlpConfigV5 on every launch. v5 adds Welcome, group-baseline, app-outcome and account recovery event kinds.
  • Strongly recommended: 37 new host performance stages for recordHostPerformance and durable edits of pending token-aware sends. Stateless Nostr event verification is optional.
  • OpenClaw enforces an inbound sender policy that denies every sender until one is configured. Hermes adds opt-in presence reactions, and Codex accepts non-image attachments.
  • Android 64-bit JNI libraries use 16 KB ELF load-segment alignment. Apple archives no longer ship LLVM bitcode.

Compatibility

Ship generated Swift/Kotlin, native libraries and C headers from this exact cohort together. MarmotEventFfi / MarmotEvent, GroupRecoveryStatusFfi / MarmotGroupRecoveryStatus, timeline records (poll projection) and HostPerformanceOperationFfi changed. Rebuild consumers and update exhaustive matches and manually constructed records; the new timeline poll field has no binding default. No existing method signature changed.

Rust hosts: MarmotAppConfig removes dev_epoch_backfill_eose_wait_ms and dev_epoch_backfill_execution_quantum_ms, adds recovery_operated_relays (it defaults to the two whitenoise.chat relays), and AppPriorNostrRoute gains replaced_at. nostr / nostr-sdk now come from a pinned fork revision.

Account databases migrate from schema 89 through 98 on first open. Back up before upgrading; downgrade is unsupported. Re-upgrade or restore a pre-upgrade database/export instead of removing migration rows. See the storage-format contract. After upgrade, an account that overflowed on 0.10.4 can show a "history may be incomplete" notice. A group that 0.10.4 already reported as automatic-recovery-failed keeps that warning until authenticated peer recovery or a rejoin clears it. The upgrade guide describes both.

Known issues

  • #2086: during a large catch-up, a member can advance more than five epochs past application messages it has not yet downloaded. Those messages cannot then be decrypted, and no notice is raised. The failure is intermittent and was already present before this release.
  • The Apple required-reason and SDK-signing questions remain tracked in #1874.

Release artifacts
