This guide follows the latest stable release. Use the documentation at your installed version’s tag when working with an older release.

Complete Marmot C symbol reference

All C functions declared in the generated header are indexed below, including constructors, commands, opaque-object operations, callbacks, free functions and compatibility shims. Read the C integration guide first; this index does not replace its memory, threading or error rules. The shared method reference provides runtime purposes and preferred/compatibility API selection. Use the exact header from the same release as the library; signatures here use C spelling, not a guessed mapping from camelCase. Full records, discriminants, callback typedefs and safety comments are in include/marmot.h.

C-only helpers manage allocation and object lifetime. A *_free takes ownership only as specified by its header contract; do not free embedded members separately. *_next calls block and use timeout/closed status values. Not all subscriptions expose callbacks or an explicit cancel operation. The source parity allowlist deliberately excludes UniFFI's three external-signer entry points: register_external_signer, login_external_signer, and begin_external_signer_onboarding.

The concrete marmot_nip46_* session adapter exposes NIP-46 login and registration without a general C signer callback interface. See the session lifecycle for mixed accounts and restart.

Prefer marmot_client_new_with_configuration when combining options, prepared chat and conversation windows for standard screens, and attachment history/access/controls for new media UI. Older primitives remain supported. marmot_set_audit_log_tracker_config is a compatibility-only C shim: its old device-label field is ignored; new integrations use marmot_set_audit_log_tracker_config_v4 and system hardware-model metadata.

Each declaration links directly to its generated header documentation. Run just binding-docs-update to refresh signatures and source anchors while preserving authored prose, then review descriptions against the changed behavior. New methods require authored guidance before their scaffold can pass. Removed/duplicate entries require explicit cleanup. just binding-docs-gate checks names, signatures and source anchors and runs regression tests; it does not validate prose. Counts are reported by the tool rather than duplicated here.

marmot_answer_sign_in

MarmotStatus marmot_answer_sign_in(const struct MarmotClient *client, const char *account_ref, const char *slot_id_hex, uint32_t response);

Answer the unrecognized sign-in in slot_id_hex. response is a MarmotSignInResponse discriminant passed as uint32_t: NotNow keeps it listed with no prompt, Reject records it as rejected in the device group's roster (now, or once this device has a quiet device group), and Dismiss only ends a prompt another device already answered. An out-of-range response is MARMOT_STATUS_INVALID_ARGUMENT; refusals such as an unknown or already answered sign-in are device-group errors. Blocks on the account worker; a rejection may commit to the device group.

Bounded local lookup of one active custom-emoji reaction's matching encrypted artwork, keyed by the exact reaction event ID within the account and chat. Call off the UI thread. Writes an owned MarmotAttachmentEntry, or NULL with MARMOT_STATUS_OK when unavailable or unmatched.
