MarmotKit API

MDK 0.15.0View source on GitHub

This guide follows the latest stable release. Use the documentation at your installed version’s tag when working with an older release.

Complete MarmotKit method reference

This reference inventories the UniFFI exports and is maintained alongside source changes. Start with the integration guide for API selection, lifecycle, localization and ownership. For the 0.14.0 changes, read 0.13.0 → 0.14.0.

This inventories runtime/object methods, free functions and host callback methods. AttachmentHistoryCursor, AccountAttachmentCursor, ChatStorageCursor, RetainedAttachmentsCursor and ChatListDraftVersionFfi are opaque objects with no exported methods. Generated disposal/concurrency helpers are platform scaffolding, not additional MDK commands. C has a separate complete symbol index, including its lifetime helpers and compatibility-only entry points.

Reading the reference

  • Signatures below use exact Rust export spelling and types; Swift/Kotlin normally expose lowerCamelCase names (attachment_local_assets → attachmentLocalAssets). Constructors and native integer/optional/list/error syntax follow generated code from your cohort.
  • async fn becomes Swift async / Kotlin suspend. A synchronous fn can perform storage I/O; run blocking operations off the UI thread. Result becomes the generated error path; Option is successful absence/stream closure as specified by the individual contract.
  • Current means supported for its stated purpose, not that every app needs it. Lower-level means an intentional custom-client/primitive surface. Compatibility means a newer path is recommended for that listed use case; it is not a formal deprecation annotation, removal promise or requirement to rewrite custom clients. Host callback means implement it in the host, not call it as a runtime command.
  • Source links lead to signatures, full doc comments and implementations. DTO field/variant definitions live in conversions, errors, Markdown types and the generated binding from the same release. Per-feature contracts in the README override no source behavior; report discrepancies.
  • Object methods use their owning type explicitly. Distinguish each next/snapshot contract: a transfer subscription delivers its initial value from next, while a screen window has a separate initial snapshot. Do not infer cancellation support from another handle.

Maintaining the reference

Run just binding-docs-update to refresh exact signatures and source anchors without rewriting the surrounding guidance. New exports receive blocking scaffolds for an author to complete and organize; removed/duplicate entries need explicit editorial cleanup. just binding-docs-gate checks that metadata and runs the companion regression tests. Descriptions and API-selection recommendations still require source-aware human review; they are not verified by the mechanical gate. Counts are reported by the tool rather than hard-coded in these pages.

Marmot::sign_out_and_wipe

Current.

pub async fn sign_out_and_wipe( &self, account_ref: String, ) -> Result<conversions::WipeOutcomeFfi, MarmotKitError>

Destructive sign-out: leave every active MLS group (best-effort), delete this device's relay-published KeyPackage slot, then wipe all local state for this account (MLS state DB, cached media/secrets, SQL account row, and the secret-store nsec). After this returns the account ref is no longer valid for any further FFI call. The returned WipeOutcomeFfi reports each stage independently so the app can show progress and a partial-failure sheet (mdk#478).

With linked devices, it first asks the account's other devices to take it out, which can take about 30 seconds: show progress meanwhile. It leaves them the chats they can take it out of, counted in groups_left_to_siblings, and leaves the rest itself. When it could not ask them in time it tries to leave every chat itself, reporting any it cannot in group_leave_failures, and sets siblings_not_reached: tell the user its other devices may still list it until the user removes it from one of them. A chat this device is no longer in is neither left nor reported. In a chat its account administers with another account, and no other of its devices is in, it steps the account down first and counts the chat as left only once it sees its removal, waiting up to about 30 seconds more for all such chats (mdk#2818). The call keeps running when it is cancelled (mdk#2628).

Marmot::open_attachment_handoff

Current.

pub async fn open_attachment_handoff( &self, account_ref: String, group_id_hex: String, target: AttachmentLocalTargetFfi, control: Arc<MediaFileTransferControlFfi>, ) -> Result<Option<AttachmentHandoffFfi>, MarmotKitError>

Write a plaintext copy of one retained attachment for an OS surface that needs a real file (the Android package installer, the share sheet, "open with", Quick Look) and lend it under a lease. Use it only for those surfaces; in-app display and playback keep using read_attachment_asset. None means the attachment is not held locally, exactly as attachment_local_assets reports it; no download is started. The copy is <account>/handoff/<lease>/<file_name>, created owner-only, where file_name is the attachment's own name made safe (basename only, no separators, control characters or edge dots, at most 128 bytes) with an extension from the media type when it had none. It stays until release_attachment_handoff, account removal, or the account worker's next start in a new process; shutdown_and_close refuses new handoffs but keeps existing copies, and removing the attachment does not revoke a lease. Each call makes a separate copy. control reports copied bytes and cancels the copy, which then leaves nothing. Cancel only through control, never by cancelling the awaiting coroutine or task: a call cancelled just as it completes can drop the lease before the host sees it, leaving the copy until the account worker's next start in a new process deletes it. A copy the disk cannot hold beyond the attachment policy's disk_reserve fails with StorageFull. Works for bodies in the media store and in the legacy database layout. See the handoff contract.
