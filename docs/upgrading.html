Upgrade guide

MDK 0.19.0View source on GitHub

This guide follows the latest stable release. Use the documentation at your installed version’s tag when working with an older release.

Upgrading MDK 0.18.0 → 0.19.0

The four 0.18.0 tags peel to 34646a577807f2b112ee031f3c164ec58aa18b64. This guide compares that release with master at 8acf460ef2f1d461db7b36e89ec5efb39374f08d, including the URL dependency fix. For the packaged source SHA, resolve the final v0.19.0 tag and match it to the WN Agent, MarmotKit and Marmot C tags and manifests. See the release notes and previous upgrade guide.

Upgrade decision Who needs to act
Required Ship matched bindings and libraries in every process opening an account. Replace stream callers, rebuild C clients and change draft deletion by omission to explicit removal.
Changed defaults A fresh thread message counts as chat and can restore a locally deleted chat. Agent replies arrive as durable messages. New groups omit the retired stream component.
Optional Add a dedicated thread view or adopt token-based tagged sends in Rust. Inline reply clients keep their existing send path.
Automatic Stored legacy thread messages are repaired. Draft attachments survive partial input saves. Linked devices redeliver invitation decisions after losing a fork.

Install and reopen

Use v0.19.0 for Rust sources, wn-agent-v0.19.0 for the connector and adapters, marmotkit-v0.19.0 for Swift/Kotlin and native libraries, and marmotc-v0.19.0 for C headers and libraries. Verify checksums, including SwiftPM's binary checksum. Stage the matching Swift file and platform privacy resource in each Apple wrapper, or the matching Kotlin sources and four JNI ABIs on Android. Update background workers and extensions in the same rollout. See distribution.

First open upgrades each account from schema 216 to 218. Migration 0217 repairs older Linux kind-1111 rows with a lowercase e and no numeric k, including parent, media, author edits and media-key references. Migration 0218 removes both stream tables, the stream timeline column and kind-1200 timeline rows. Retained source events and durable kind-9 final messages survive. Chat-list projection version 5 rebuilds list rows once. Allow time for the first open of a large account. Schema 218 requires the upgraded library. A rollback to 0.18.0 requires a separate pre-upgrade copy of the data. The shared and directory databases retain their 0.18.0 schemas (5 and 3).

Replace live preview consumers

Use ordinary durable messages for agent output. Remove startAgentTextStream, watchAgentTextStream, openAgentPublisher, their handles, callbacks and stream DTOs. Remove the stream activity/start cases in MarmotEventFfi and MessageUpdateFfi, both stream triggers in TimelineUpdateTriggerFfi and agentTextStreamJson on timeline messages and reply previews. A received kind-1200 start has no visible row or message notification. A kind-9 final renders as a normal message. The engine refuses new outgoing starts, including a pre-upgrade queued start when it drains. The latter raises GroupEvent::QueuedIntentRefused.

New groups omit component 0x8006. KeyPackages refresh once to drop the send and fanout roles. MDK continues to advertise support and the receive role for existing groups. Rust exposes the component in AppGroupRecord::unknown_components. In the group's MLS state, MarmotKit lists its ID in requiredAppComponents and C lists it in required_app_components. Create and invite still enforce the group's required roles. Rust embedders must remove the stream runtime APIs, QUIC exporter and dependencies on transport-quic-stream, transport-quic-broker and agent-stream-compose. See the runtime, engine and shared types inventories.

For connector clients, the wire label is still v2. Replace all seven stream_* requests with a single send_final for the completed reply and remove stream responses and stream_update handlers. An obsolete request closes the connection without a response. Upgrade the gateway plugin and connector together. Drop --enable-streaming and --quic-candidate from Hermes/OpenClaw installer invocations and remove broker/candidate flags from bootstrap. Older --no-quic invocations are accepted as a no-op. Older OpenClaw configuration keys quicCandidates, streaming and blockStreaming are ignored. The Hermes configure helper drops --streaming, --transport and --configure-global-streaming. See the agent-control contract.

Remove wn stream, TUI /stream commands, stream subscription updates and stream-specific JSON errors from CLI automation. The daemon drops stream_watches from status, and message, group and timeline JSON drop agent_text_stream. See the CLI changelog.

Read and send threads

Inline clients render replyToMessageIdHex as a one-level quote and use replyToMessage to answer any row, including a thread message. This creates a kind-9 inline reply. A thread view groups by thread.rootMessageIdHex and nests by thread.parentMessageIdHex. Both timeline records and reply previews gain nullable thread; previews also gain their own nullable replyToMessageIdHex. Update host-created fixtures and retain placement when rendering a deleted placeholder. Kind-1111 thread messages expose Markdown content tokens and arrive as NewMessage.

From a thread view, send text, already-uploaded attachment references or both. Pass the immediate parent's ID. MDK resolves its row locally and builds the root and parent tags. It refuses a missing or deleted parent, or a missing root whose kind and author cannot be recovered from a stored ancestor. Supply additional application tags only (up to 64 and 16 KiB total). MDK owns E/K/P/e/k and builds imeta from typed attachments. Mentions follow chat rules. Inspect the send summary's acceptance disposition to distinguish publication, queuing and unknown completion. The following illustrative calls run inside an async Swift task or Kotlin coroutine.

let summary = try await client.sendThreadMessage(
    accountRef: account, groupIdHex: group, parentMessageId: parent,
    text: "I can pick that up.", attachments: [], tags: [])

val summary = client.sendThreadMessage(
    accountRef = account, groupIdHex = group, parentMessageId = parent,
    text = "I can pick that up.", attachments = emptyList(), tags = emptyList())

Thread messages with a parent move the chat up, count toward unread and mentions, notify in the foreground and on wake, and reach WN Agent live and on replay. A fresh thread message can bring a locally deleted chat back into the list under the same rules as a fresh kind-9 message. Deleted content caught before connector output is suppressed. A deletion after output arrives as a later event. An author can edit and delete thread messages. Admin removal of another member's message still applies only to kind 9. The release provides placement on existing rows. Paged descendants, thread summaries and per-thread read state are planned separately in #2787. See the wire forms, display rules and fixtures.

Save draft attachment edits

saveMessageDraftInputsIfRevision is a local, revision-checked edit. Supply Retained IDs in the desired order, Inline to add or replace data, and the new Removed case for a user deletion. Named surviving attachments come first, then unnamed attachments in their stored order. Removing a missing ID is harmless. Retaining a missing ID raises InvalidMessageDraft. Removing or replacing a file-backed attachment releases the file. Pass the latest revision and use the returned selection for the next edit. On MessageDraftRevisionConflict, reload and reapply the user's edit. Update exhaustive Swift/Kotlin switches. The whole-list saveMessageDraftIfRevision API still replaces the list. See the draft and staging contract.

C hosts

Recompile every caller against the matching header and library. MarmotTimelineMessageRecord and MarmotTimelineReplyPreview lose agent_text_stream_json and gain a nullable MarmotTimelineThreadRef *thread. The preview gains reply_to_message_id_hex. Read these nested pointers within the owning result's lifetime and release the containing result with its matching free function. For marmot_send_thread_message, pass attachment and tag arrays with their lengths, check the returned status and free the resulting summary with marmot_send_summary_free. Run blocking C calls off the UI thread.

Zero-initialize MarmotMessageDraftAttachmentSaveInput. To delete, set its new removed_id and leave retained_id null. Both set returns MARMOT_STATUS_INVALID_ARGUMENT. Remove publisher/stream calls, handle types, callbacks and free functions. The stream variants disappear from MarmotMessageUpdate, MarmotEvent and MarmotTimelineUpdateTrigger. Discriminants after the removed variants shift. Recompile switches and translate any host-persisted numeric values using the header that produced them. See the C symbol inventory.

Rust submissions and storage

The workspace lockfile includes url 2.5.9 for RUSTSEC-2026-0592. Rust hosts building MDK with their own lockfile should check that it resolves url to a patched version (2.5.9 or later) and update it if necessary.

Rust hosts can use MarmotAppRuntime::submit_tagged_text, submit_tagged_reply, submit_tagged_edit_for_local_send and submit_custom_event. Persist a client token before submission. For an edit, pass the original send's token and a distinct edit token. Local acceptance gives a token and message ID. Query local_send_status for progress. A token is local to one account on one device and to one group. After restart, an identical retry there returns the original message ID while the device retains the token association, unless the stored status is Rejected. Another device can admit the same request as a new message. Deleting the group or expiring the source message also removes the association, so a later retry can create a new message. The token binds the whole request, including text, reply target, attachment references, ordered tags, custom kind and, for an edit, the original send's token. Reusing the token for changed inputs or a rejected submission raises InvalidAppMessagePayload. Use a new token for the corrected or rejected request. Untagged requests keep their prior hashes. App tags travel inside the encrypted event. For chat, use typed media instead of an imeta tag. The reply owns its e and q, the edit its e; custom events follow the existing send_custom_event rules for reserved kinds. These token-based additions are Rust runtime APIs.

Storage consumers constructing timeline records must supply the new thread fields, and TimelineMessageTarget gains thread_message. Match the new StoredMessageDraftAttachmentInput::Removed variant. To preserve omitted attachments in direct SQLite calls, use update_message_draft_if_revision. See the storage changelog.

Acceptance checks for consuming apps

  • Verify artifact provenance, build the actual app and extensions, and reopen a populated 0.18.0 account offline. Check a legacy Linux thread, its media and edits, and a durable agent final after migration.
  • Send a nested thread message from a thread client and answer it from an inline client. Check quotes, placement, unread/mention counts and notifications across foreground, background and reconnect. Exercise parent deletion.
  • Stage a file, save text before the composer loads the attachment, then reopen. Verify the file survives. Explicitly remove it and reopen again. Race a stale save against staging and handle the revision conflict.
  • Run a connector and its matching gateway. Verify a completed reply arrives once and replay suppresses content deleted before delivery to the agent. For Rust token-based sends, restart between admission and recording the result, then retry with the original token and verify the same ID.
  • With two linked devices, accept or decline an invite across a device-group fork. Verify both converge after reconnect. Measure first-open time and foreground responsiveness on a representative device with a large history.

The source comparison establishes the contracts above. Packaged binaries, consuming-app builds and real-device upgrade results require verification against the published cohort.
